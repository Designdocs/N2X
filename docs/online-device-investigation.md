# 在线 IP 异常取证与 N2X 修复

## 已确认的事实

本次案例的九个 IPv4 地址均属于 APNIC 分配记录中的 CN 地址段。日本节点看到大陆客户端的公网来源地址属于正常行为；异常是已经没有对应连接的地址仍被反复报告为在线。

2026-10-18（UTC+8）的只读取证确认：

- 异常节点实际由容器内的 `xboard-node` 提供服务，并非同机其他端口上的 N2X。
- 16:42:35，节点发出的原始 `report.devices` 消息已在同一个账号下包含完整九个地址。
- 16:42:18 至 16:42:50，节点本机连续九次连接检查，这九个来源地址的连接数均为零。
- 面板 WebSocket 工作进程仍根据节点上报刷新这些地址的时间。面板的“最近活跃”是收报时间，不能替代真实连接或认证时间。
- 保留的节点日志能确认其中四个地址曾成功认证到该账号，另四个地址见于该账号的历史订阅访问记录；最后一个地址缺少足够的历史认证记录。
- 当前数据库及该节点下发名单中，该账号的认证标识没有重复；已核对的节点用户在线记录中，九个地址只归到这个账号。

据此可以确认节点侧存在残留在线状态，不能把这九条记录当作九台物理设备同时登录，也不能据此认定客户电脑异常或订阅泄漏。历史日志不足以证明所有地址对应哪一台电脑。

为避免发布客户信息，本仓库不保存账号、实际来源地址、节点地址、访问凭据或原始报文。

## 旧后端中复现的缺陷

运行版本对应 `cedar2025/Xboard-Node` 的 `0a29338e1f102a462363ce3527417029f89bab28`。

其 `delConn` 发现用户的旧 `unlimitedIPs` 表存在便返回，即使待关闭的连接已经记入 `limitedIPs`。在隔离验证中，先完成一次状态迁移，再创建和注销九条连接，在线快照仍保留九个地址；普通注销对照组为零。

该缺陷与现场残留现象一致，但现有审计记录不足以证明这个账号具体经历了哪次历史状态迁移。不能把可复现路径写成已还原的生产触发事件。

## N2X 修复范围

N2X 没有上述两张表切换时的同一条注销路径。核对 N2X 时另外确认了相关问题：原有设备快照只包含本周期新分发的连接，读取后会清空，导致仍在使用的长连接下一周期消失；完全离线时不发送快照，HTTP 通道也缺少明确的用户移除记录。

本次修复包括：

1. 按仍存活的认证连接生成在线快照，不再用“本周期新建连接”代替在线状态。
2. 连接登记固定绑定认证用户和规范化后的来源 IP。同一用户、同一 IP 的多条连接按引用计数保留，最后一条关闭时移除。
3. 注销回调持有原始登记对象，策略更新不会改变其清理目标；账号撤销会清除记录，旧连接的延迟关闭不能删除重建后的登记。
4. Xray 使用现有 writer 生命周期和 context 取消回调清理，不替换 mux 依赖的具体 pipe reader。上传半关闭不会提前移除仍在下载的连接。
5. sing 核心的 TCP、UDP 路径都在成功通过认证和规则检查后登记，并在关闭或 context 取消时清理。底层关闭失败也会释放登记。
6. 每周期继续发送快照。对已离线用户发送非空 JSON 对象中的空 IP 数组，以兼容 HTTP `alive` 的逐用户清理；失败的移除记录保留到下一次重试。
7. 保留现有流量门槛筛选；已报告且仍存活的连接不会因为某个周期只有少量流量而消失。上报任务重启时串行处理快照和离线重试状态。

保留现有宽松／严格模式、设备限额、容差和 CDN 豁免规则。本次不改变协议配置、认证凭据或服务器部署。

## 验证与切换观察

回归覆盖长连接跨周期、共享公网 IP、多用户隔离、IPv4 映射地址、策略更新、账号撤销及重建、延迟注销、并发快照、半关闭、关闭失败、空快照和离线重试。发布包在本地构建后上传，不通过 Release 事件启动线上构建。

运营切换时停止旧后端，避免同一节点编号继续被两套进程同时上报。切换后观察：

- 持续使用的连接跨多个周期仍在快照中。
- 网络切换后旧连接结束，其地址不再由新后端上报。
- 最后一条连接关闭后，后续快照清空该用户，面板按上报或现有缓存期限消退。
- 账号之间的 IP 归属不发生变化。

公网 IP 仍是网络出口标识，不是物理设备唯一标识。日本节点的实际切换和切换后的生产观察由运营方完成，本次本地验证不能替代该阶段。
