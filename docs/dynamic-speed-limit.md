# 面板动态限速

## 行为

- 每个实际节点、每个后端实例独立判断。同一个节点用户身份的设备、IP、TCP/UDP 和上下行共用一个速率上限。普通账号、独立 IP、独享服务分别使用面板下发的身份。
- 默认每 5 秒采样；收集完整 180 秒滑动窗口，其中至少 85% 的时间严格超过 50 Mbps，处罚为合计 5 Mbps、持续 1800 秒。支持面板配置 1 小时、8 小时和自定义时间。
- 短暂低速采样仍保留在窗口内，默认允许累计约 27 秒低于阈值。按实际采样时长加权，比例支持 1% 至 100%，100% 等价于严格连续超速。超过两个采样间隔的缺口属于未知时段，重新收集完整窗口。惩罚期间不叠加、不续期；结束后重新收集完整观察窗口。
- 触发及到期恢复以 5 秒采样粒度执行。面板请求在独立同步流程中运行，网络等待不会暂停本地观察或处罚计时。
- 管理员、员工以及节点规则选中的用户、套餐、独享服务由面板在用户列表中下发 `dynamic_speed_exempt: true`。其普通凭据及独立服务凭据均豁免动态处罚，固定套餐、节点、本地限速仍取非零值中较低者。角色晋升或新增豁免解除正在生效的动态处罚，取消豁免重新观察。
- 已有连接始终持有稳定控制器；面板启停、处罚、解除和固定速率更新无需重建监听或让用户重连。凭据轮换保留同一节点用户 ID 的处罚；删除用户则清除处罚并撤销旧控制器。

## 面板配置契约

公共节点配置新增可选字段。策略版本 2 支持超速占比；运行状态版本 3 增加豁免名单应用回执，管理端在名单版本不匹配时保持待应用。与协议专属参数分开，HTTP 和 WebSocket 同步共享配置生成路径。

```json
{
  "dynamic_speed_limit": {
    "version": 2,
    "revision": 1,
    "exemptions_revision": 0,
    "enabled": true,
    "threshold_mbps": 50,
    "sustain_seconds": 180,
    "over_threshold_percent": 85,
    "limit_mbps": 5,
    "penalty_seconds": 1800
  }
}
```

速率使用十进制 Mbps，`Mbps × 1000000 ÷ 8` 为每秒字节数；观察使用实际成功转发字节，不乘计费倍率。限速读取的累计计数独立于账单上报清零；账单读取使用原子 Swap 避免并发增量丢失。

持续时间支持 30 至 3600 秒、按 5 秒递增；处罚时间支持 60 至 86400 秒；处罚速度必须为正且小于触发阈值。非法配置保留当前有效运行配置并重试。

面板明确下发的参数优先；缺失或 null 的数值字段补默认 50 Mbps、180 秒、85%、5 Mbps、1800 秒，缺失启用状态默认关闭。显式非法值仍拒绝，保留当前有效规则。完全没有面板策略时不自动启用，已有本地配置继续保留。

规则的 `revision` 由面板生成。阈值、观察窗口或超速时间占比变化会重新观察；处罚速度变化即时更新已有处罚；处罚时长变化只影响新处罚。显式关闭清除动态限制，恢复基础速率。旧面板没有字段时保留旧本地配置；一旦采用面板策略，字段意外消失保留最后有效策略并报告状态异常。旧本地动态规则与面板策略互斥。

## 豁免名单一致性

豁免在面板节点策略中配置，子节点继承整份规则：用户覆盖其账户和名下服务凭据，套餐匹配该凭据实际套餐，独享服务或独立 IP 服务只匹配所选服务。条件取并集，管理员和员工始终豁免。N2X 只接收解析后的布尔标记，不处理邮箱或套餐、服务 ID。

面板配置的 `exemptions_revision` 与 HTTP 用户响应头 `X-Dynamic-Speed-Exemptions-Revision` 必须一致。响应仍为 `{users: [...]}`，JSON、MessagePack 均支持；缺少响应头按 0 兼容旧面板。只有成功解码并应用用户后才更新 `exemptions_applied_revision`。304 保留已取得名单的版本；应用失败会清除用户 ETag 以重新拉取，错误响应、半截 JSON 和非法版本号不会被确认。

配置比名单先到时暂停新处罚并重开观察，不把等待时间当作超速时长。已有处罚照常到期，收到豁免身份后立即清除其动态处罚，静态速度和设备约束继续生效。修改名单会通知节点重新拉取，无需重建监听。

## 实例与本地恢复

HTTP 和 WebSocket 均携带稳定 `instance_id`，面板按节点和实例分别显示状态，适用于多个后端共用公网出口。默认实例标识由主机及节点配置散列生成；克隆主机或同一配置运行多个进程时，可为每个进程设置不同的 `N2X_INSTANCE_ID`（1 至 128 个英文字母、数字、点、横线、下划线）。

处罚记录默认保存在 `/var/lib/N2X/dynamic-speed-limit/`。目录需要节点进程可写，可用 `N2X_DYNAMIC_LIMIT_STATE_DIR` 指定独立持久目录。文件名只包含散列，内容只有节点用户 ID、处罚及事件，不含 UUID、令牌、来源或目的地址；目录 0700、文件 0600，临时文件写入和 Sync 后原子替换。

进程内使用单调时间计算持续时间和到期；重启后按原绝对到期时间恢复仍有效的处罚，已过去的停机时间也计入处罚。未完成的观察窗口重新开始。读写失败在节点日志及面板状态中显示，异常记录不用于恢复处罚。

多个实例分别维护处罚，本地状态目录与实例标识应保持稳定。面板断线期间使用最后有效规则，到期恢复照常执行。

## 状态和手动解除

`metrics.dynamic_speed_limit` 包含支持版本、启用状态、已应用修订号、已应用豁免名单修订号、当前参数、观察/处罚人数、已应用的超速比例、当前处罚及其实际超速占比（最多 200 条）、最近 50 条事件和解除命令回执。详细事件同时写入节点日志。

状态文件读写异常通过 `state_error` 上报；面板意外省略已接管的规则通过 `policy_error` 上报。多个实例使用相同公网出口时，管理端同时展示出口 IP 和稳定实例标识。

解除命令携带节点用户 ID、精确处罚 ID、命令 ID 及到期时间，通过现有配置下发通路传递。它只解除该实例的该次处罚，重复投递不会解除后续处罚。界面收到节点回执后才显示解除成功。未连接实例显示待应用，旧后端显示需要升级。

## 升级与回退

1. 部署 X-Board 新迁移与兼容接口，所有新策略默认未配置。
2. 更新 N2X，并确认状态中的动态限速支持版本、实例归属及本地状态目录权限。
3. 更新管理端构建产物，再逐节点开启。规则保存成功和节点实际应用分别显示。
4. 回退前在面板显式关闭，等待所有在线实例确认新修订号；离线实例恢复通信后也应先确认关闭，再回退程序。新增数据库列可以保留。

豁免名单按节点配置；处罚仍按实际节点及后端实例独立维护。测试、构建和运行验收全部本地执行；具体验证结果见本次工作记录。

## 本地验证

基础检查：

```sh
GOEXPERIMENT=jsonv2 GOWORK=off go test -mod=readonly ./api/panel ./node ./conf ./limiter ./common/rate
```

生产标签为 `sing xray with_quic with_grpc with_utls with_wireguard with_acme with_gvisor`。对应 race 检查覆盖共享控制器、角色变化、同步阻塞时继续采样、sing TCP/UDP 以及 Xray 的普通派发和直接转发入口。直接转发的上传 reader 与下载 writer 共用同一控制器，嗅探读取同样受控。大 UDP 报文限速时保持报文边界与目的地址元数据。

真实本地 socket 用例验证已建立的无限速连接转为处罚后立即共享限速、解除后继续传输，以及独立计费计数。持续时间检测使用可控时钟和累计字节，实际速度使用真实等待验证。

初版于 2026-11-15 在 macOS ARM64 完成测试及 race 验收；本地离线 Docker 的 Linux ARM64 验收通过 49 个用例（含子用例），并完成 macOS ARM64、Linux amd64/arm64 的完整生产标签构建。Linux amd64 本轮只做交叉构建。TCP 回环基线的无限速包装路径为 5086–5375 MB/s、0 allocs/op，原始连接为 4946–5276 MB/s；这是本机单连接基线，多实例生产负载仍按灰度步骤观察。


本轮三类豁免扩展在本地通过完整生产标签的 19 个 Go 测试包，以及 Linux ARM64 离线容器中的 30 个策略/API/限速/节点用例（含子用例）。新增路径和 Xray 的 race 通过，sing 动态限速相关 race 通过。扩展运行完整 sing race 时发现 TUIC 依赖 CachedConn 的 Close/Read 竞争，已在变更前 `abd17bc` 干净源码复现，保留为独立问题。本地构建 macOS ARM64、Linux amd64/ARM64 完成；Linux amd64 已进行模拟版本启动检查，动态限速运行回归覆盖 macOS ARM64 与 Linux ARM64。
